# Hackathon Infrastructure Compliance

This document describes how Vynora's current MVP maps to requested hackathon infrastructure while preserving the working open-source build.

## Currently Implemented

Vynora currently ships as a Next.js App Router application with:

- Supabase Auth for authenticated users
- Supabase Storage for private conversation audio
- Supabase Database tables for sessions, jobs, extracted entities, memory, actions, and processing state
- Trigger.dev workers for asynchronous conversation processing
- Deepgram-first transcription with Gemini fallback
- Gemini / Google AI for structured understanding
- Google Calendar OAuth and approval-based event creation

The implementation is intentionally human-in-the-loop: external actions are suggested first and only execute after user approval.

## Designed For Integration

### MongoDB

MongoDB is the planned production database layer for flexible intelligence documents generated by the Memory Engine and Action Engine. The strongest fit is for records whose shape can evolve over time, including:

- conversation memory snapshots
- long-term person and preference profiles
- relationship graph documents
- extracted agent context
- agent action traces

The current MVP uses the Supabase schema as the durable hackathon data layer. A MongoDB adapter can be added at the memory persistence boundary without changing the frontend framework, authentication model, upload pipeline, or worker orchestration.

### Google Cloud Agent Builder

Google Cloud Agent Builder is the planned production agent orchestration layer. The cleanest integration point is after the Understanding Engine, where raw conversation audio has already been converted into structured context.

Agent Builder can use that context to:

- ground assistant responses in conversation history
- retrieve memory profiles and user preferences
- generate follow-up recommendations
- pass proposed external actions back into Vynora's approval-based action queue

This keeps agent behavior explainable and prevents automated execution without user confirmation.

## Next Production Step

The next production implementation step is to add provider adapters while keeping the current application shape:

- `MongoMemoryStore`: persists memory documents and relationship snapshots to MongoDB.
- `AgentBuilderOrchestrator`: sends validated conversation context to Google Cloud Agent Builder.
- `ActionApprovalBridge`: receives suggested actions and keeps the current approve/dismiss flow.

These adapters can be introduced behind the existing intelligence engine boundaries, so the MVP remains stable while the infrastructure expands.
